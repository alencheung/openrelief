# OpenRelief — Phase 1: Feature Discovery & Role Mapping

**Tech Stack**
- **Frontend**: Next.js 15 (App Router) + React 18, TypeScript (strict), Tailwind CSS + CVA + Radix UI, MapLibre GL JS, Turf.js, Zustand, TanStack Query v5
- **Backend**: Next.js API Routes (App Router), Cloudflare Workers (Edge Functions), Upstash Redis (rate limiting), Sentry
- **Database**: Supabase Postgres (Auth, RLS, Realtime)

**Codebase analyzed**: `Z:\SourceCode\openrelief` (43 app-router files: 16 pages, 22 API routes, 1 callback, 4 root special files)

## User Roles & Authentication States

### RBAC Roles (`user_profiles.role`)
| Role | Defined | Enforced in code? |
|---|---|---|
| `citizen` | default on signup | implicit fallback in `api-security.ts` |
| `responder` | in CHECK constraint | **NOT enforced anywhere** |
| `coordinator` | in CHECK constraint (20240117 migration) | **NOT enforced anywhere** |
| `moderator` | in CHECK constraint | `allowedRoles: ['admin','moderator']` in audit/emergency/trust |
| `admin` | in CHECK constraint | `allowedRoles: ['admin','moderator']` in audit/emergency/trust |

### Trust-Score Tiers (primary capability system, `trust-integration-helpers.ts`)
| Tier | Score | Key permissions |
|---|---|---|
| very_low | 0.0–0.2 | read_public only; no reporting/voting |
| low | 0.2–0.4 | read_public, comment; limited reporting |
| medium | 0.4–0.6 | read, comment, report, vote |
| high | 0.6–0.8 | + moderate |
| very_high | 0.8–1.0 | + admin |

### Authentication States (10)
1. Unauthenticated/anonymous · 2. Loading/verifying · 3. Authenticated standard · 4. MFA-pending (UI not shipped) · 5. Insufficient trust (403) · 6. Insufficient role (403) · 7. Account locked/suspended (dead code — column absent) · 8. Sybil high-risk · 9. Suspicious/blocked IP · 10. Emergency mode (relaxed trust gate)
